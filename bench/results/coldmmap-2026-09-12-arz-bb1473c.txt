# local/coldmmap -- what a cold mapping costs in pages, not in bytes on disk
# lexindex 2.1.0 at bb1473c, 2026-09-12, arz (Ryzen 7 5800HS, Zen 3), rustc 1.98.1, clean tree
#
# Storage: NVMe (HFM001TD3JX013N) under LUKS, btrfs. 38 GB RAM, so "cold" here means this file's
# page cache was dropped, not that the machine was short of memory.
#
# Every size table in this repository measures the blob. A process that maps one and answers a
# thousand queries never reads most of it, and what decides whether an index fits a container is
# the resident set, not the file. Columns, all bytes per key except the two latencies:
#   file      the blob on disk
#   mapped    resident straight after `load_mmap`, before a single query -- the control for the
#             page-cache drop, which is `posix_fadvise(POSIX_FADV_DONTNEED)` and needs no root
#   after 1k  resident after 1 000 random member lookups
#   after 1M  resident after a further 1 000 000
#   cold ns   the mean over those first 1 000 lookups, page faults included
#   warm ns   the mean over the next 1 000 000
#
# Each structure is measured twice. The `(random)` rows call `madvise(MADV_RANDOM)` on the mapping
# -- which `load_mmap` does not do -- so a fault brings in its own page instead of a readahead
# window. The difference between the two is the kernel's readahead, and reading it as a knob is
# the point of the row.
#
