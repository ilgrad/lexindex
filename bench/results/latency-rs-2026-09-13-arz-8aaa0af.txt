# cargo run --release --example bench -- 1 M dictionary-word bigrams, six runs back to back
# lexindex 3.0.0 at 8aaa0af, the v3.0.0 tag checked out in a clean worktree
# 2026-09-13, arz (Ryzen 7 5800HS, Zen 3, 8c/16t, 16 MB L3), rustc 1.98.1, Fedora 44, kernel 7.2.4
# Each lookup cell is the minimum of five timed passes after a warm-up pass, probes shuffled.
#
# The six runs fall into two clock regimes, and the published table quotes the second one:
#
#   runs 1-2  minutes after a reboot, cold part, load 0.66 at the start
#   runs 3-6  the same binary, same machine, steady state, load 0.88 -> 1.58 (the benchmark itself)
#
# Every row is 18-44 % slower in runs 3-6 than in runs 1-2, controls included -- StringIndex +34 %,
# std HashMap +23 %, BTreeMap +28 %, FxHash +23 %, CompactHash +44 %. A change that moves the
# controls by as much as the subjects is the machine, not the code: the part sustains its boost
# clock for the first two runs and settles afterwards. Runs 3-6 agree within 2.3 % of each other
# and match the session the 2.1.0 table was measured in, so they are the comparable regime and the
# table quotes the minimum over them. Runs 1-2 are kept here because discarding them silently is
# how a table ends up quoting a number nothing else can reproduce.
#
# The serialised sizes are identical in all six runs -- they are not a timing measurement.
