DictIndex per-block offsets: packed against a superblock base — 2026-09-12, arz (Ryzen 7 5800HS, 8 cores, 38 GB, Fedora 44)

Harness: local/dictbench (release), the same source on both trees, so this is a before/after on the same binary
shape: /usr/share/dict/words sorted and deduplicated (479 823 keys), probes = all words shuffled with a fixed
seed, every id for the reverse lookups, five rounds per block size, variants alternated within a round, min per
variant, ns per probe. StringIndex is the control: no edit here can reach it.

Before is 4c85dca, the BDX2 header/suffix split, with `head_ends` a u32 a block and `blocks` a u64 a block.
After is 6c699c0: both arrays are one u64 base every 64 blocks plus a delta of the width the corpus asks for
(10 bits for the head ends, 13 for the block starts at block 32), and a head or a block's data is read as one
`pair` — the two entries share a base and the word their deltas are cut from.

The two runs of each tree take the block sizes in opposite orders, minutes apart on the same machine and load.

Summary, min over the two runs:

                        k=16     k=32     k=64    k=128    k=256
  bytes/key   before    4.352    3.522    3.103    2.894    2.785
              after     3.790    3.245    2.966    2.827    2.752
              delta   -12.9 %   -7.9 %   -4.4 %   -2.3 %   -1.2 %
  per-block   before    1.250    0.625    0.313    0.156    0.078
  metadata    after     0.688    0.348    0.176    0.089    0.045

  id, member  before    287.6    309.3    330.8    387.7    487.9
              after     290.8    307.3    332.3    386.9    485.8
  key_into    before    117.1    164.7    256.1    442.3    813.4
              after     116.5    167.5    266.1    466.7    865.0
              delta     -0.5 %   +1.7 %   +3.9 %   +5.5 %   +6.3 %

`id` does not move: the search reads a pair where it read two adjacent words, and the arrays it walks are
smaller. `key_into` pays 2 instructions an entry walked — measured with perf as +2.2 % instructions at block
256 for +2.9 % cycles, with branch misses and L1 misses flat, so it is code the compiler lays out differently
around the block walk rather than a stall. Marking `pair` `#[inline(never)]` moved 1.5 % of it back onto `id`
(850 against 865 ns at 256, id 490 against 487) and was not taken: `id` is the more common call. Hoisting the
head read above the walk was worse than both (872-874 ns).
