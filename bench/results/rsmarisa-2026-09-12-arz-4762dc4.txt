# local/rsmarisacmp (throwaway crate; rsmarisa is NOT a lexindex dependency) over the corpus set
# lexindex 2.1.0 at 4762dc4, 2026-09-12, arz (Ryzen 7 5800HS, Zen 3), rustc 1.98.1, clean tree
#
# Supersedes rsmarisa-2026-09-12-arz-d82e296.txt, which was one corpus (the Fedora word list) and
# two configurations. Both sides are curves here: rsmarisa at its smallest, default and fastest
# cache levels against DictIndex at 32, 128 and 1024 keys per block, over every corpus
# `bench/corpora.py` pins at 100 000 and 1 000 000 keys.
#
# Size is rsmarisa's `io_size()`, asserted once against the file `save()` writes, which is the same
# definition the Python tables use. Latency: 20 000 probes, half members and half strangers spelled
# in the corpus's own alphabet, shuffled with a fixed seed -- the rules `bench/_probes.py` uses,
# though not the same draws, the generators being different. Five rounds, the six lanes alternating
# within each and reversing with its parity, first round discarded, minimum per cell.
#
# Note on the configurations: at nominally the same setting rsmarisa is 1.5-12 % larger than the
# C++ marisa measured by `bench/sweep.py` (3.823 against 3.707 B/key on words-100000 at three
# tries and a normal cache). The flag words are not identical between the two, so read each
# library's own curve rather than the pairs.
#
